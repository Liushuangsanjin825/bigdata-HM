## 一、Executive Summary（执行摘要）

本项目基于 Kaggle H&M 个性化时尚推荐数据集，围绕“为每位顾客预测未来最可能购买的 12 件商品”构建推荐系统。通过 EDA、时间顺序本地验证、规则召回、LightGBM 排序和 SHAP/消融实验，我们发现 H&M 推荐任务高度依赖短期趋势、用户近期行为和商品热度变化；随机打乱验证会造成严重数据穿越，因此必须采用时间切分验证。最终项目形成了两级方案：规则融合 Baseline 用于稳定召回和提交格式保障，LightGBM baseline 用于候选重排并显著提升线上分数。实验显示，规则 Baseline 的 Public LB 为 `0.01828`，LightGBM 版本最高达到 Public `0.02702` / Private `0.02680`；新特征消融进一步证明“商品近期热度占比”比单纯价格匹配更有效。

### 2.2 业务背景与问题定义

H&M 是典型的时尚电商/零售场景，用户购买行为受到季节、趋势、年龄、价格、渠道和近期偏好的共同影响。推荐系统要解决的问题不是简单预测“热门商品”，而是为每位顾客在未来一周内推荐最多 12 个最可能购买的商品。好的推荐应同时满足三点：能覆盖全部用户、能命中用户未来真实购买、并且把命中的商品尽量排在推荐列表前部。

本项目使用 Kaggle 官方指标 `MAP@12` 衡量推荐质量。该指标关注前 12 个推荐结果的命中情况和排序质量，因此候选召回质量与排序质量都非常关键。

### 2.3 EDA 中的关键发现

1. **购买行为具有明显时间趋势**：H&M 服装消费存在季节性和阶段性波动，近期趋势对未来一周预测非常重要。因此模型中特别构造了近 7 天、近 30 天商品热度和趋势类特征。

   ![月度交易趋势](../doc_images/fig_4_1_monthly_trend.png)

2. **渠道和品类偏好存在差异**：不同销售渠道、商品部门、商品组的购买分布不同，因此规则 Baseline 中加入了渠道热门、部门热门、年龄段热门等多路召回。

   ![渠道占比](../doc_images/fig_4_2_channel_share.png)

   ![热门商品组分布](../doc_images/fig_4_3_top_product_group.png)

3. **用户活跃度差异明显**：部分用户有较强近期购买行为，而大量用户行为稀疏。针对活跃用户，模型更依赖用户近期历史；针对低活跃或冷启动用户，模型使用趋势热门和全局热门兜底。

   ![用户最近购买间隔](../doc_images/fig_5_1_user_recency.png)

### 3.2 验证策略

- **验证方式**：Time-based Split（按时间顺序切分）
- **训练集**：每折只使用验证窗口之前的历史交易
- **验证集**：训练截止日之后未来 7 天
- **评估指标**：MAP@12
- **不使用随机 K 折的原因**：推荐系统预测的是未来行为，商品热度、用户兴趣和季节趋势都随时间变化。如果随机打乱交易记录，训练集中可能出现验证期之后的购买行为，模型等于提前看到未来趋势，会造成数据穿越和本地分数虚高。

## 四、Findings（核心发现）

### 发现 1：H&M 推荐强依赖短期趋势

- **C（事实）**：交易数据具有明显时间波动，近 7 天和近 30 天商品热度对验证窗口命中有较强影响。新特征消融中，`item_pop_ratio_30d_all` 将 Local CV MAP@12 从 `0.030038` 提升到 `0.030730`。
- **I（洞察）**：服装消费受流行趋势和季节变化影响明显，只看全历史热门会稀释近期趋势，短期热度占比能更好捕捉“正在流行”的商品。
- **A（行动）**：在 LightGBM 特征中加入商品近期热度、购买人数和热度比例特征，并在最终建议中保留 `item_pop_ratio_30d_all`。

### 发现 2：用户近期历史是强召回信号，但不能完全依赖历史复购

- **C**：规则 Baseline 中用户近期历史权重最高，调参后最优配置为 `user=40.0`，明显高于渠道、部门、年龄、趋势等权重。
- **I**：用户过去买过什么对短期推荐很重要，但 H&M 服装场景存在新品、流行趋势和长尾商品，单纯复用历史商品会覆盖不足。
- **A**：项目采用“用户历史 + 趋势热门 + 人群/部门热门”的多路召回，并在 LightGBM 中对候选商品重新排序。

### 发现 3：盲目扩展候选会引入噪声

- **C**：尝试加入 `product_type`、`garment_group`、`colour`、`section` 等属性召回后，部分提交 Public 分数升高，但 Private 分数下降。例如某次新增候选数量版本 Public 达到 `0.02738`，但 Private 只有 `0.02642`，低于最初 LightGBM 的 `0.02680`。
- **I**：新增候选不等于有效候选，属性相似商品可能“看起来相关”但不一定会被用户购买。候选噪声会干扰排序模型，导致泛化不稳定。
- **A**：后续将候选策略改为保留 baseline 强候选，再追加少量稳健召回；同时默认关闭噪声较大的颜色和 section 召回。

### 发现 4：Gain 高不一定代表真实贡献高

- **C**：SHAP/消融实验发现，`candidate_rank`、`user_avg_price`、`user_recency_days` 在 LightGBM gain 中排名较高，但移除后 MAP@12 反而提升。
- **I**：树模型分裂增益反映的是建树过程中的局部收益，不一定等价于最终推荐指标 MAP@12 的真实提升。
- **A**：增加消融实验和 `LGBM_DROP_NOISY_FEATURES` 开关，用本地时间验证而不是单纯 gain 排名决定特征去留。

## 五、特征工程与消融实验

### 5.1 特征设计思路

| 特征名 | 业务假设 | 数据来源 |
|:---|:---|:---|
| `user_txn_30d` | 近期活跃用户更可能继续购买 | transactions |
| `user_recency_days` | 最近购买时间越近，短期复购概率越高 | transactions |
| `item_pop_7d` | 近期热卖商品更可能在未来一周继续被购买 | transactions |
| `item_buyers_7d` | 购买人数比单纯销量更能反映流行广度 | transactions |
| `ua_cnt` | 用户曾多次购买同一商品，说明偏好更强 | transactions |
| `ua_recency_days` | 用户-商品最近交互越近，延续购买可能性越高 | transactions |
| `item_pop_ratio_7d_30d` | 短期热度相对 30 天热度上升，说明商品趋势增强 | transactions |
| `item_pop_ratio_30d_all` | 近期热度占历史热度比例高，说明商品仍有当前流行性 | transactions |
| `price_diff_user_item` | 商品价格越接近用户历史均价，越符合用户消费层级 | transactions |

### 5.2 新特征单变量消融实验

本实验遵循“一次只加一个变量”的原则。基础模型不包含以下 3 个新特征，然后分别加入其中一个特征，记录 Local CV MAP@12。

实验分数：

```text
base                              = 0.030038
+ item_pop_ratio_7d_30d           = 0.030059
+ item_pop_ratio_30d_all          = 0.030730
+ price_diff_user_item            = 0.029983
```

| 特征 | 加入后 MAP@12 | ΔMAP | 判定 |
|:---|---:|---:|:---:|
| Baseline（不含 3 个新特征） | 0.030038 | — | — |
| `item_pop_ratio_7d_30d` | 0.030059 | +0.000021 | 暂时保留，贡献很小 |
| `item_pop_ratio_30d_all` | 0.030730 | +0.000692 | 保留 |
| `price_diff_user_item` | 0.029983 | -0.000055 | 放弃 / 暂不加入 |

> **截图占位**：插入 4 次 `LGBM validation ... MAP@12=...` 日志截图。

结论：`item_pop_ratio_30d_all` 是最有效的新特征，说明商品近期热度占比对推荐排序有明显帮助；`price_diff_user_item` 没有带来收益，可能说明价格匹配在当前特征粒度下不足以解释 H&M 用户短期购买行为。

## 六、失败分析

### 失败尝试 1：直接扩大属性召回

1. **动机**：希望通过 `product_type`、`garment_group`、`colour`、`section` 等属性偏好召回更多潜在命中商品，提高候选覆盖。
2. **方法**：在 LightGBM 版本中加入属性偏好召回，并为候选来源加入 `source_product_type`、`source_garment_group`、`source_colour`、`source_section` 等标记。
3. **结果**：部分版本 Public 分数上升，但 Private 分数下降，例如 Public `0.02738` / Private `0.02642`，低于最初 LightGBM Private `0.02680`。
4. **归因**：属性相似不等于短期购买意愿，颜色和 section 等属性可能引入大量噪声候选，并削弱原 baseline 强候选。
5. **教训**：推荐系统中候选扩展必须控制噪声，不能只追求候选数量。后续应保留 baseline 强候选，再谨慎追加少量高质量候选。

### 失败尝试 2：价格匹配特征未带来提升

1. **动机**：用户历史均价可能反映消费层级，商品均价与用户均价接近时可能更容易被购买。
2. **方法**：新增 `price_diff_user_item`，表示用户历史均价与商品平均价格差值。
3. **结果**：Local CV MAP@12 从 `0.030038` 降到 `0.029983`，变化量为 `-0.000055`。
4. **归因**：H&M 数据中的价格经过归一化，且服装短期购买更受趋势、品类和用户历史影响，粗粒度价格差无法有效解释购买行为。
5. **教训**：价格特征需要更细的上下文，例如折扣、新品、品类内价格分位数，而不是简单使用绝对均价差。

### 失败尝试 3：单看 LightGBM Gain 选择特征

1. **动机**：使用 LightGBM 自带 gain 排名快速判断特征重要性。
2. **方法**：按 gain 选 Top-5 特征，并进行逐个移除消融。
3. **结果**：`candidate_rank`、`user_avg_price`、`user_recency_days` 虽然 gain 高，但移除后 MAP@12 反而提升。
4. **归因**：树模型 gain 反映建树局部增益，不一定等于推荐最终指标贡献；部分特征可能导致模型过拟合局部排序模式。
5. **教训**：特征去留必须以时间验证下的 MAP@12 消融结果为准，而不能只看模型内部重要性。

## 七、Discussion（讨论）

### 7.1 业务洞察的总结

H&M 推荐系统的核心不是简单地推荐全局热门商品，而是在“用户历史偏好”和“近期流行趋势”之间取得平衡。活跃用户的近期购买记录非常有价值，但时尚商品趋势变化快，用户未来购买也会受到季节、新品和短期热度影响。因此，多路召回和时间敏感特征比静态用户画像更重要。

比较出乎意料的是，某些看似合理的属性偏好和价格匹配特征并没有稳定提升分数。这说明服装推荐中的“相似”并不总是转化为“会买”，模型需要更谨慎地控制候选噪声。

### 7.2 技术决策的依据

项目采用“规则召回 + LightGBM 排序”的架构，原因是 H&M 用户和商品规模较大，直接对全量用户-商品组合建模不可行。规则召回先把候选空间压缩到每人几十个商品，LightGBM 再基于用户、商品和交互特征做重排。这种结构既保证可运行性，也能利用时间窗口验证控制数据穿越。

### 7.3 局限性与改进方向

当前方案仍有一些不足：

1. 候选召回仍主要依赖规则，召回覆盖率存在上限。
2. LightGBM 训练只使用有限时间窗口，可能对不同测试子集泛化不稳定。
3. 商品图片和文本描述尚未真正进入主模型。
4. 冷启动用户主要依赖趋势热门和全局热门，个性化程度有限。

如果继续优化，优先方向是：多窗口训练、提交融合、商品相似召回、文本/图像 embedding 召回，以及更细粒度的品类内价格特征。

## 八、Recommendations（建议）

1. **针对短期流行趋势，建议强化“近期热度”推荐位**  
   H&M 服装消费具有明显短期趋势，商品近 30 天热度占比对模型提升最大。业务上可以在首页和推荐流中增加“近期热卖/趋势单品”模块，并按年龄段或部门做轻度个性化。

2. **针对活跃用户，建议优先利用近期历史行为重排推荐**  
   用户近期购买历史是强信号。对最近有购买行为的用户，应优先推荐其历史偏好部门、服装组和趋势商品的交集，而不是单纯推全局热门。

3. **针对低活跃和冷启动用户，建议使用稳健热门兜底而不是过度属性扩展**  
   属性召回可能引入噪声，尤其是颜色、section 等特征。对低活跃用户，应优先使用近期全局热门、年龄段热门和渠道热门，避免用过细属性制造不稳定推荐。
